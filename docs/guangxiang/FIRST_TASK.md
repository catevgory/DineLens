## 本次目标

用户搜索餐厅或查看分析进度时，如果后端离线、请求失败或需要人工处理，页面应解释原因并给出可执行的下一步。恢复进度查询时继续查看原任务，避免因重试创建重复任务。

本次首先推进这一项代码任务。200 条真实评论的独立人工标注仍是已有 P1 工作，需要另行取得队友的真实样本并开展，不能用生成数据代替。

## 已核对的代码现状

以下结论来自对上游 main 分支的静态阅读，尚未通过浏览器复现：

- `web/api.js` 的请求层直接解析 JSON 并拼接接口错误，尚未统一转换网络错误、非 JSON 响应和业务错误。
- `web/analysis.js` 的 `poll()` 在请求失败后只显示提示，不再安排下一次轮询，暂时断网可能导致进度停止更新。
- `start()` 在提交完成或失败后重新启用按钮。需要区分“请求正在提交”“已有任务运行”和“结果不确定”，防止重复创建。
- 搜索已有按钮禁用、finally 恢复和无结果提示。应保留已有行为并补齐缺失场景，避免重复实现。

上游代码：[api.js](https://github.com/Jc0876/DineLens/blob/main/web/api.js)、[analysis.js](https://github.com/Jc0876/DineLens/blob/main/web/analysis.js)。

## 开发范围

1. 统一用户可读的中文错误提示，区分断网、后端离线、配置缺失、会话异常及其他请求失败。保留状态码等诊断信息供程序使用，页面不直接显示原始 JSON 或 HTML。
2. 搜索失败后保留餐厅、城市和来源输入，恢复搜索按钮，并明确提示用户如何再试。
3. 轮询中断时保留当前任务 ID，提供“恢复查询进度”操作；恢复操作只读取原任务，不重新 POST /jobs。
4. 处理 queued、collecting、analysing、done、failed、cancelled、needs_operator 状态。needs_operator 提示联系操作人员处理平台验证，避免承诺页面能自行重试后端任务。
5. 任务提交期间禁止重复提交。提交结果不明确时，应保留该次幂等键供同一次请求重试使用；启动另一个明确的新任务时才生成新键。
6. 增加必要的页面提示区域和按钮，沿用现有页面风格与 api.js 的匿名会话、Cookie 和 CSRF 机制。
